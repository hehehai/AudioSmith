# AudioSmith's patches to mlx-audio-swift

`scripts/fetch-engine-deps.sh` checks out upstream [Blaizzy/mlx-audio-swift](https://github.com/Blaizzy/mlx-audio-swift) at the commit it pins and applies these patches in name order into `engine/.build/deps/mlx-audio-swift`, which `engine/Package.swift` uses as a local package. Keep each patch small and send it upstream; drop it when upstream has the fix.

| Patch | Why |
|---|---|
| `0001-kokoro-eval-before-yield.patch` | mlx-swift 0.32 gives each thread its own default stream. Kokoro's `generateStream` yields an unevaluated array from its own `Task`; the consumer then crashes evaluating it ("There is no Stream(gpu, N) in current thread"). Evaluate before yielding. |
| `0002-whisper-task-and-language-detection.patch` | `WhisperModel.task` ("transcribe"/"translate"), and language detection when none is given (the logits after `<|startoftranscript|>`, as OpenAI's `detect_language`), so results report the language. |
| `0003-chatterbox-language-and-spaces.patch` | The regular Chatterbox tokenizer splits on whitespace, so spaces must be spelled `[SPACE]` as in Resemble's tokenizer; the multilingual model also takes lowercase NFKD text, a `[lang]` prefix, Cangjie codes for Chinese (`Cangjie5_TC.json`) and jamo for Korean (Resemble's MTLTokenizer, MIT). |
| `0004-kitten-read-voices-npz.patch` | The KittenTTS 0.8 repos ship their voices as `voices.npz`, which the loader refused ("convert to safetensors"): read the stored zip of float32 `.npy` arrays directly; and refuse inputs over 510 phonemes (ALBERT has 512 positions; longer ones crashed MLX) as Kokoro does. |
| `0005-moss-cancellable-transcribe.patch` | MOSS-Transcribe-Diarize (thread #48; from Dicta's patch 0006, same author): `MossTranscribeDiarizeModel.transcribe(audio:generationParameters:prompt:onText:)`, which runs in the caller's task and throws `CancellationError` (checked between encoder batches, prefill steps and tokens) where `generate` traps on any error, takes the instruction (hotwords), and reports the text as it is decoded (the engine's progress). The Whisper encoder runs the 30 s chunks 2 at a time instead of all in one batch (the same result, without gigabytes of attention scores for long inputs). `sanitize` transposes the encoder's convolution weights by their shape, not by whether the checkpoint is quantized, so conversions that keep PyTorch's layout (majentik's 8-bit) load too. |

| `0006-s3gen-cosyvoice2-fixes.patch` | CosyVoice2's acoustic stack as SoulX-Podcast uses it (thread #80): HiFT's last LeakyReLU has slope 0.01 (`F.leaky_relu(x)` in CosyVoice2's and Chatterbox's hifigan.py), not 0.1 as between its upsampling layers — Chatterbox changes too; `CausalMaskedDiffWithXvec(hiftUseInterpolation:)` builds CosyVoice2's 24 kHz sine source (SineGen2), whose linear resampling now follows torch's `align_corners=False`; `inference(noise:)` takes the flow's starting noise (CosyVoice2/SoulX draw fresh noise per call), and the fixed noise table of the regular CFM is drawn from a state of its own instead of reseeding MLX's global generator; `deterministicVocoderSource` drops the source's random phase and noise for parity tests. |
| `0007-qwen3-speaker-embedding.patch` | Qwen3-TTS Base clones from a reference without its transcript (thread #90). With `refText` nil the port fell back to no voice at all; now it clones from the clip's speaker embedding alone, as upstream's `x_vector_only_mode`. That embedding is computed as upstream's `extract_speaker_embedding` does (`mel_spectrogram`: magnitude spectrum, librosa's Slaney mel filters up to 12 kHz, natural log clamped at 1e-5, reflect padding of (n_fft − hop) / 2): the port's Whisper-style mel (power spectrum, HTK mel scale, log10, max − 8, (x + 4) / 4) gave an embedding that sounded like nobody (CAM++ 0.1–0.2 instead of 0.55–0.65). ICL clones (with `refText`) keep the port's mel so their voices stay as they were: their voice comes mostly from the reference codes, and upstream's mel there measured no clear gain. The dub clones lines in another language than the speaker's clip this way. |
| `0008-qwen3-frame-cap.patch` | Qwen3-TTS (VoiceDesign, CustomVoice and Base: one generation loop) stopped every take at `max(75, text tokens × 6)` codec frames (0.48 s per token), and a caller's `maxTokens` could only lower that: slow designed voices were cut off mid-reference (thread #91: 5 of 118 voices, clones then said the missing half). Now `Qwen3TTSModel.effectiveMaxTokens`: without `maxTokens` (the default parameters no longer set 4096) the cap is `max(75, tokens × 10)` (0.8 s per token); a `maxTokens` the caller sets replaces it, raising or lowering it; never more than `maxFramesHardCap` 4096 frames (327 s), so a run that never ends still stops. |
| `0009-voxcpm2-chinese-tokens.patch` | VoxCPM2 (thread #165): feed multi-character Chinese tokens one character at a time, as upstream's Python (`mask_multichar_chinese_tokens`) does; the port read Chinese garbled (CER 76 % → 5 %). Upstream mlx-audio-swift #356 (2026-10-30), backported unchanged; drop at the next pin. |
| `0010-voxcpm2-bf16.patch` | VoxCPM2: keep the bf16 weights' dtype through RoPE, the causal mask, the time embeddings and the CFM's guidance arithmetic, instead of promoting every step to fp32 (1.6× slower). Upstream #380 (2026-11-07), adapted to the pin's pre-MaterializedArray code; drop at the next pin. |
| `0011-voxcpm2-continuation-parameters.patch` | VoxCPM2: `generate(text:refAudio:refText:parameters:)` with `VoxGenerateParameters` — diffusion steps and guidance per request (the port read them from the config only); with `refText` the reference is also continued from its transcript after the isolated reference prefix (OpenBMB's combined ref + continuation mode, "ultimate cloning"; the prompt patches are left-padded and the last 3 decoded before the take and trimmed, as `_generate`'s `context_len`); a take is capped at target tokens × 6 + 10 patches (the port's cap was 8192 patches, 22 minutes) and one that reaches it without the stop head firing is retried with the next seed, up to 3 takes (`retry_badcase`). The logic follows OpenBMB/VoxCPM's `voxcpm2.py` (Apache-2.0); no code copied. The generic `generate` calls it, so `generateStream` gets the cap too. |

Make a patch: change the checkout in `engine/.build/deps/mlx-audio-swift`, `git diff > engine/patches/mlx-audio-swift/000N-name.patch`, then rebuild (the stamp in the checkout notices the new patch and re-applies the series from a clean checkout).
